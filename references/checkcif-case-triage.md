# 从案例学checkCIF：检查、处理与回复

触发：阅读完整配套报告或准备警报回复。教程001–003、084、086、106提供了问题分类和回复线索；历史阈值和他人的解释不当作当前证据。先读当前报告中警报的官方说明，含类型/等级、数值及所指原子/反射。

## 按警报选择检查

| 类型/常见线索 | 要核实什么 | 下一步与完成条件 |
|---|---|---|
| DIFMN02、PLAT097/098：残差密度 | 峰/谷位置及最近原子、图形、原子类型、吸收/截断与无序 | 数据/模型对照能解释具体位置；不能只写“重原子效应” |
| PLAT241/242、Hirshfeld类 | 邻居与PART/对称关系、占有率、Uij、元素和键级 | 先修真实原因；ADP限制需有依据，不因警报就全加ISOR |
| PLAT420/430：供体/短接触 | 周期邻居、互斥组分、H位置、D–H···A角与距离 | 证明是合理相互作用或修正H；不能仅用短距离认定氢键 |
| THETM01、缺失反射/PLAT910类 | 实际θ范围、波长、束挡、缺帧、覆盖与OMIT记录 | 还原层对照或报告真实缺失；“高角弱”不是删除理由 |
| PLAT934：大加权偏差 | 当前HKL、Fo/Fc/σ、重复观测、帧/位置和数据来源 | 个别OMIT对照留痕，不按名单无条件删除 |
| PLAT930、PLAT987：孪晶线索 | 未合并数据、晶胞度量、漏对称、异常散射、候选律 | 按[孪晶分支](hydrogen-twin-solvent-cases.md)核验，警报不是诊断结论 |
| 高R1/wR2/Rint、低强反射比例 | 数据集/σ/权重、完整度、模型遗漏与对称 | 分清上游还原及模型问题；小R不能自动证明“结构无疑” |
| 元数据/组成/F000/密度不一致 | 来源、位点多重性、占有率、溶剂、电荷、嵌入记录 | 按[元数据说明](cif-metadata.md)修正有来源字段，再出配套报告 |

类型/等级不是固定处理配方，当前检查条件以[IUCr检查目录](https://iucrdata.iucr.org/x/services/cif/datavalidation.html)和具体报告为准。历史教程003是截至2021年的目录，不能当作实时规则库。

## 回复写什么

对每条实际警报记录：

1. **对象**：当前报告编号、原子/反射/字段、实测数值、文件哈希和验证模式。
2. **调查**：看过的原图/差图/日志、相关数据范围及独立证据。
3. **处理**：相对父版本改了什么，哪些对照有效、无效或未能完成。
4. **结果**：当前数值/图形变化，仍存在什么限制，结论能支持到哪一步。

“多块晶体均如此”“已做若干尝试”“存在高度无序”等只在确有记录时写。原论文的仪器、原子名、残峰位置和重测经历不能移到当前样品。没有充分解释时保留待解决，不能自动填“完全可接受”。

VRF是记录作者回应的机制，不会使差数据变好，也不证明根因消除。重测、改模型、换数据、改元数据后重新生成报告；CIF-only明确缺少结构因子核验。报告/回复绑定本次实际CIF/FCF。

## 提交前配套核查

从原CIF提取嵌入RES/HKL用于再精修时保留原文件，确认是否完整及校验信息；FCF不是原始未合并HKL的等价替代。更换引擎或版本时根据实际输出核查嵌入记录和最终文件，不以旧GUI菜单位置证明数据齐全。

软件版本、温度、采集/还原/吸收步骤、H/无序/孪晶/掩膜说明按实际处理写。SHELXL的TEMP通常用摄氏度，CIF实验温度用K，按当前手册换算。根据目标期刊/数据库核对提交要求，不能把一个旧审稿案例推广为所有投稿入口的统一规定。

命名或绘图修改仍要确认最终CIF的标签与图一致；若改了模型中的名称，生成新的配套文件，避免直接编辑表格使其与嵌入RES不符。
